# GitHub Copilot Instructions

## Project Overview
- **Name**: blog.nazrulhisham.net
- **Type**: Next.js Blog Platform with Authentication & CMS
- **Purpose**: Personal tech blog with user authentication, post management, and engagement features
- **Stack**: Next.js 12, React 17, MongoDB, Passport.js, MDX, Bootstrap 5

## Architecture & Directory Structure

### Core Directories
- **`pages/`**: Next.js pages and API routes (file-based routing)
  - `_app.js`: Global wrapper with AuthProvider
  - `_document.js`: Document shell
  - `api/`: API routes separated into `public/` and `secure/`
  - `blog/`, `secure/`: Protected pages requiring authentication
- **`components/`**: Reusable React components
- **`lib/`**: Business logic and utilities (auth, posts, token service)
- **`models/`**: Mongoose schemas (User, BlogPost)
- **`middlewares/`**: Express-style middleware (database, passport, auth)
- **`utils/`**: Helper functions (dbConnection, fetcher, secureApiRoute)
- **`posts/`**: MDX blog post files (static content)
- **`styles/`**: CSS files (fonts.css)

### API Structure
- **Public routes** (`pages/api/public/`): No authentication required
  - Posts: `most-hit.js`, `most-like.js`
  - Post details: `[slug]/hits.js`, `[slug]/likes.js`, `[slug]/give-like.js`
- **Secure routes** (`pages/api/secure/`): Passport JWT authentication required
  - User management: `users.js`, `users/[id].js`
  - Post management: `posts.js`, `posts/[slug].js`, `posts/[slug]/activate.js`
  - Account: `account/user-profile.js`, `account/token-identity.js`

## Authentication & Security

### Key Security Practices
1. **Password Hashing**: Use bcryptjs (BCRYPT_SALT_ROUNDS from env)
2. **JWT Authentication**: Passport.js with `passport-jwt` strategy
3. **Role-Based Access Control**: Check user roles (`'admin'`, etc.) in middleware
4. **Protected Routes**: Use `useAuth()` hook on client, `secureApiRoute` on server
5. **Tokens**: Manage with `token-service.js`, store in session cookies
6. **Environment Variables**: Store secrets in `.env.local` (see `.env.local.example`)

### Auth Flow
- Login: POST to `/api/public/account/token` with email/password
- Token issued and stored in session cookie (`kookie-user-auth`)
- Protected routes verify JWT via Passport middleware
- Logout: Clear cookie via `handleUser(null)` in auth context

### Role-Based Middleware Example
```javascript
export const ensureAdminIsInRoles = (req, res, next) => {
  if (req.user?.roles?.includes('admin')) {
    return next()
  }
  return res.status(403).end()
}
```

## Best Practices to Follow

### Code Quality
1. Use semantic HTML and ARIA labels for accessibility
2. Separate concerns: API logic ≠ component logic
3. DRY principle: Extract reusable components and utilities
4. Error handling: Always validate inputs and handle failures gracefully
5. Comments: Explain WHY, not WHAT (code should be self-explanatory)

### Security Checklist
- ✅ Validate all inputs on both client and server
- ✅ Never expose secrets in frontend code
- ✅ Use HTTPS in production
- ✅ Implement CORS properly
- ✅ Hash passwords with bcryptjs
- ✅ Validate authentication tokens
- ✅ Use environment variables for sensitive data
- ✅ Implement rate limiting for auth endpoints
- ✅ Escape HTML output to prevent XSS
- ✅ Validate user permissions before data operations

### Performance
- Optimize MDX post rendering with static generation
- Use Next.js Image component for images
- Lazy load components where appropriate
- Minimize bundle size (no unnecessary dependencies)
- Implement pagination for large data sets

### Testing Notes
- No formal test setup currently (consider adding Jest/React Testing Library)
- Manual testing: Use `npm run dev` and browser
- Test auth flows thoroughly (login, logout, token refresh)

## Common Tasks

### Adding a New Blog Post
1. Create `.mdx` file in `posts/` with frontmatter
2. Use `getSortedPostsData()` and `getPostData()` to display

### Adding a New API Endpoint
1. Create file in `pages/api/` (public or secure folder)
2. Use `next-connect` for middleware support
3. Implement Passport JWT check for secured routes
4. Return JSON responses

### Adding a New Protected Page
1. Create page component in `pages/secure/`
2. Wrap with `PageSecuredShell`
3. Use `useAuth()` hook to check user status
4. Redirect to login if unauthorized

### Adding User Roles/Permissions
1. Add role to user document in database
2. Create role-check middleware in `middlewares/`
3. Apply middleware to route handlers
4. Verify on client with `user.roles` from context
